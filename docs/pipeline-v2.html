The whole pipeline

One run = one clip, one athlete. Side views only. Bar-only clips go through --calibrate and end at C3. Once the skeleton check passes, S1 and S2 run in parallel; S2 → S3 finds the attempt windows, and S4 poses only inside them. Each step skips itself when its outputs are up to date (see Running steps). Every step writes an overlay video, so each one can be checked by eye. Stop = the run ends with a message and does nothing else.

Running steps

Steps talk only through files in out/<clip>/, so any step can run alone once its input files exist. A step never runs its producers for you. If an input is missing, it stops and names the step to run.

CommandRuns
pipeline.py clip.MOV --athlete jiriall steps; skips a step whose outputs exist and are not stale
… --only S3S3 alone, always rerun, from the existing input files
… --from S3S3 and every later step (S4, S5, S6, S7, S8, S9, report)
… --forcererun every step, ignoring the hashes
… --only S3 --lift-m 0.08step parameters as flags, part of the step hash
… --intended squat|power|muscleintended snatch type for S8 (wins over labels.csv)
pipeline.py --calibrate bar.MOV --athlete jiri --only C3refit the skeleton without rerunning pose

Stale outputs: each step writes <stage>.meta.json with a hash of its input file contents, its parameters, its STAGE_VERSION constant, and (for S5/S6 and later) the hashes of skeleton.json and scale.json. A step is stale when that hash differs from the stored one. A run rebuilds only stale steps and the steps downstream of them; an identical rerun output changes nothing downstream. Outputs are written to a temp file and renamed, so a crash never leaves a file that looks done. The side panel lists each step's input files and their producers.

Stop exit codes: 2 = no skeleton for the detected side, 7 = no height for the athlete (run with --height), 8 = facing ambiguous or near side disagrees, 3 = clip unusable (incl. broken frame times), 4 = plate track failed, 5 = proportions off the skeleton (another person?), 6 = bar-only clip given to analyze (use --calibrate).

Decisions (settled in review, 2026-10-09)

1. Lift result (S8). lift_result = completed / failed / unknown, with a reason. completed: in one overhead run the arms stay locked (elbow ≥ 165° only on frames where the wrist is seen), the lifter stands up (S7's standing border exists: knee within 5° of its max while overhead), holds ≥ 0.5 s (frame times; 1 s once the protocol asks for it) (the hold ends where S7 sees the hub fall 5 cm, so a drop shows as a short hold); and the performed type matches the intended type. Reasons: no_overhead, elbow_unlocked, no_standup, hold_short, type_mismatch, low_confidence (hip or knee filled, or hidden and not filled because S5 had no scale, where the check relies on it: standing, or bar_lowest for the type; or the plate lost during the hold). Thresholds are placeholders until checked against labels.csv.
2. Snatch type (S8). From S7's events. muscle: knee drops ≤ 10° below its full-extension value after the bar's peak (no rebend). power: rebends, hip above knee at the catch (thigh above parallel). squat: hip at or below knee at the catch. split / unclear: unknown (unsupported_type). Hip or knee filled at the catch → unknown. Intended type: --intended > labels.csv > inferred (= performed). Any intended ≠ performed → failed: type_mismatch; skipped when intended_source = inferred or performed is unknown.
3. Final label (report). Final label: completed_clean / completed_with_errors / failed / unknown. completed_clean = completed and no error-severity finding from S9; completed_with_errors = completed with ≥ 1. S9 has no error-severity rule yet (no source says a fault costs the lift), so completed_with_errors cannot occur yet. S9 never changes lift_result.
4. Skeleton validity + clip scale. One skeleton per athlete and side. S5 rescales it per clip from a standing window, else from visible-knee frames. Any camera distance works, also an unknown one (no limit on the factor; changed 2026-10-19 from "within 15% of the calibration"). The guard against another person is a proportions check that does not depend on distance: thigh / shank off the skeleton's by > 10% → stop. Recalibrate for another person; the camera must stay side-on.
5. Validation. labels.csv (clip, attempt, result, intended_type; plus reason, fault, note) replaces filename labels. No agreement target (labels.csv holds the intended lift, not what was performed): S8 reports agreement on T1–T8 and names the cause of each miss (upstream error, wrong label, performed ≠ intended). Full S8 rules: .scratch/plan/D-judge.md (decided 2026-10-23); new clips get added over time. Plate options: --radius a:b only (no --view, side views only), no filename parsing.
6. Squat snatch (#26). S7 computes the same v2 events for every type; S8 classifies. If the v2 events turn out wrong for squat catches, #26 adds type-specific event rules in S7.
7. run_all.sh. Done in #68: deleted with the rest of v1 (scripts, studies, phases/spread/angles).
