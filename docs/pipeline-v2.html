uv run python scripts/pipeline.py <clip.MOV> --athlete <id>. Click a box or a table row: the panel on the right gives the step's input, code, output and overlay. Colour = code status: exists in src/snatch/ exists in studies/, must move new code

The whole pipeline

One run = one clip, one athlete. Side views only. Bar-only clips go through --calibrate and end at C3. Once the skeleton check passes, S1 and S3 run in parallel; S3 → S5a finds the attempt windows, and S2 poses only inside them. Each step skips itself when its outputs are up to date (see Running steps). Every step writes an overlay video, so each one can be checked by eye. Stop = the run ends with a message and does nothing else.

Running steps

Steps talk only through files in out/<clip>/, so any step can run alone once its input files exist. A step never runs its producers for you. If an input is missing, it stops and names the step to run.

CommandRuns
pipeline.py clip.MOV --athlete jiriall steps; skips a step whose outputs exist and are not stale
… --only S5S5 alone, always rerun, from the existing input files
… --from S5aS5a and every later step (S2, S4a, S4b, S6a, S7, S8, report)
… --forcererun every step, ignoring the hashes
… --only S5a --lift-m 0.08step parameters as flags, part of the step hash
… --intended squat|power|muscleintended snatch type for S7 (wins over labels.csv)
pipeline.py --calibrate bar.MOV --athlete jiri --only C3refit the skeleton without rerunning pose

Stale outputs: each step writes <stage>.meta.json with a hash of its input file contents, its parameters, its STAGE_VERSION constant, and (for S4a/S4b and later) the hashes of skeleton.json and scale.json. A step is stale when that hash differs from the stored one. A run rebuilds only stale steps and the steps downstream of them; an identical rerun output changes nothing downstream. Outputs are written to a temp file and renamed, so a crash never leaves a file that looks done. The side panel lists each step's input files and their producers.

Stop exit codes: 2 = no skeleton for the detected side, 7 = no height for the athlete (run with --height), 8 = facing ambiguous or near side disagrees, 3 = clip unusable (incl. broken frame times), 4 = plate track failed, 5 = clip scale failed, 6 = bar-only clip given to analyze (use --calibrate).

Decisions (settled in review, 2026-10-09)

1. Lift result (S7). lift_result = completed / failed / unknown, with a reason. completed: in one overhead run the arms stay locked (hub over the shoulder and hub–shoulder distance ≥ 90% of arm length; elbow ≥ 165° only on frames where the wrist is seen), the lifter stands up (hip above knee, knee ≥ 160°), holds ≥ 1 s (frame times) and the bar drops < 10 cm; and the performed type matches the intended type. Reasons: no_overhead, elbow_unlocked, no_standup, hold_short, dropped, type_mismatch, low_confidence (hip or knee filled where the check needs it, or the plate dropped out during the hold). Thresholds are placeholders until checked against labels.csv.
2. Snatch type (S7, merged from the old S5b). From S6a's events. muscle: knee drops ≤ 10° below its full-extension value after the bar's peak (no rebend). power: rebends, hip above knee at the catch (thigh above parallel). squat: hip at or below knee at the catch. split / unclear: unknown (unsupported_type). Hip or knee filled at the catch → unknown. Intended type: --intended > labels.csv > inferred (= performed). Any intended ≠ performed → failed: type_mismatch; skipped when intended_source = inferred or performed is unknown.
3. Final label (report). completed_clean = completed and no error-severity finding from S8; completed_with_errors = completed with ≥ 1. Until S8 has rules, the report shows only completed / failed / unknown. S8 never changes lift_result.
4. Skeleton validity + clip scale. One skeleton per athlete and side. S4a rescales it per clip from a standing window, else from visible-knee frames; it must be within 15% of the calibration, else stop. Recalibrate when the camera setup changes.
5. Validation. labels.csv (clip, attempt, result, intended_type) replaces filename labels. S7 counts as done at 100% agreement on the existing clips; new clips get added over time. Plate options: --radius a:b only (no --view, side views only), no filename parsing.
6. Squat snatch (#26). S6a computes the same v2 events for every type; S7 classifies. If the v2 events turn out wrong for squat catches, #26 adds type-specific event rules in S6a.
7. run_all.sh. Delete it once pipeline.py works, and update the verify skill, prototype/README.md and results/33 in the same PR.
